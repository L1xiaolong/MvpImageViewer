# 内存优化实测记录

日期：2026-11-11。Windows x64，Qt 6.11.0 / MSYS2 Release 构建。
基线包含上一轮缩略图写入和后台轮询优化；本次对照只改变 ImageLoader 的预览缓存管理。

## 口径

- 每个场景启动独立进程，重复 3 次，表格取中位数；1 MiB = 1,048,576 字节。
- Windows `GetProcessMemoryInfo.PrivateUsage` 是进程私有提交量，不等同于物理工作集，也不包含完整独立显存占用。
- 完整程序每 50 毫秒采样，取启动后 3～5.5 秒的稳定区间中位数；6 秒截图退出，不将截图缓冲计入稳定值。
- 解码流程使用生产 ImageLoader 和真实解码器，依次加载 512、2048 预览、原图、关闭使用者、缓存重开及清空缓存；没有界面和 GPU，不能当成完整软件内存。
- 固定测试图：4 张 4000×3000 JPEG，2 张 2400×1600 的 16 位 PNG。由 memory_benchmark 的固定公式生成，两版使用同一组文件。
- 复测在独立目录中串行进行，避免构建和其他基准任务干扰。后台系统活动仍会造成波动。

## 改动和验证

清理已经可由更大预览或原图提供的旧编码图片预览。仅在新帧通过全局缓存预算检查后清理同一文件版本、参数和解码器身份下的旧预览。晚到的小预览仍会交给请求者，但不再重复进入缓存。

原图精度、色彩转换、透明通道、缩略图缓存、384 MiB 默认预算和预加载策略保持不变；RAW/YUV 的源平面及 CPU fallback 不使用此路径。仍被界面引用的旧预览保持有效，像素释放沿用原来的异步回收机制。

新增回归覆盖缓存重开不重复解码、旧画面引用有效、不同解码器身份隔离、乱序完成、超预算原图保留备用预览、非标准尺寸预览及 RAW 表示保留。完整的 18 项回归已通过，原工作目录清理后还在独立构建中复测缓存回归。

前后各 3 次截图核验通过：JPEG、PNG 的图片显示区域逐像素一致（排除元数据文字栏），空白窗口全图一致。坐标和结果记录在 render-checks.json；仅代表本机与本组测试图。

## 复现

启用 MVPVIEW_BUILD_TESTS，构建 memory_benchmark 和 MVPImageViewerQml。PATH 应包含匹配的 Qt/MSYS2 运行库。修改前保存基线 EXE，然后分别对两版运行：

```powershell
memory_benchmark.exe generate FIXTURES
python scripts/benchmark_memory.py memory_benchmark.exe FIXTURES loader.json --loader
python scripts/benchmark_memory.py MVPImageViewer.exe FIXTURES ui.json
```

GUI 测试会启动窗口、截图并退出，像正常应用一样读写设置；运行时不要同时操作其他应用实例。
